03 findings
F-001 · HIGHNeeds review

Object-level authorization gap

A peer fixture returned object metadata where an authorization denial was expected.

Potential impact

A signed-in user could potentially view another user’s record if the server trusts a client-supplied object reference without checking ownership.

Safe confirmation

Compare owner and peer test accounts against an inert fixture; verify status, body, and audit events. Do not modify or delete data.

Recommended fix

Enforce server-side object authorization on every read and write, return a consistent denial, and add negative regression tests.

F-002 · HIGHNeeds review

API schema boundary signal

The approved fixture accepted an unexpected optional field during a read-only API validation.

Potential impact

Unexpected fields may create mass-assignment or business-logic risk when authorization and input validation are not enforced server-side.

Safe confirmation

Run a schema comparison using inert values and a non-mutating fixture; confirm unknown fields are rejected and logged.

Recommended fix

Use an allowlisted request schema, bind writable fields explicitly, and test each role against the same API contract.

F-003 · MEDIUMNeeds review

Session rotation after privilege change

The session fixture did not rotate its identifier after a simulated privilege boundary change.

Potential impact

Session fixation or stale-session exposure can extend access beyond an intended authentication or privilege transition.

Safe confirmation

Record session identifiers before and after the controlled transition, then verify expiry, cookie flags, and revocation.

Recommended fix

Rotate identifiers at authentication and privilege changes, revoke old sessions, and enforce Secure, HttpOnly, and SameSite flags.
